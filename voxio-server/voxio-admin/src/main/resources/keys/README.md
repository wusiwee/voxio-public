# 开发用国密密钥（随仓库发布）

这两份文件是**随仓库发布的开发用密钥**，不是任何真实环境的凭据：

| 文件 | 内容 | 用途 |
| --- | --- | --- |
| `master-sm4.json` | `sm4KeyHex`（SM4 主密钥）+ `keyVersion` | 经 SM3-HKDF 派生字段加密、密钥包装等子密钥 |
| `sm2-server.json` | SM2 密钥对 + `keyVersion` | 保护聊天会话密钥的线上传输 |

## 什么时候会被用到

`SmKeyStore` 的装载顺序：

1. `voxio.crypto.key-dir` 目录里已有同名文件 → 用目录里的（**部署方自带密钥的正规姿势**）；
2. 目录可写但没有密钥 → 首次启动自动生成并落盘到该目录；
3. 目录不可创建/不可写（只读挂载、容器里没有可写 HOME 等）→ 回退读这里。

也就是说：正常情况下这两份文件不会被读取，它们只是第 3 种情况下的兜底，
保证「clone 下来导入 SQL 就能直接 `java -jar` 起来，不会因为国密目录不存在而报错」。

## 安全边界

默认 `voxio.crypto.enabled=false`，聊天与业务字段都是明文，这两份密钥实际不参与数据加解密。

**要开启加密，绝对不要沿用这里的密钥** —— 它们已经公开在仓库里，任何人都能拿它们解出你的数据。
正确做法：先删掉 `key-dir` 指向的目录（或清空），启动让它生成属于你自己的密钥，
确认 `key-dir` 下已存在两份文件、且日志里没有「已回退到 classpath:keys/」这条 WARN，再打开加密开关。
